How rebind turns a web page or a PDF into an EPUB

By the end, you can explain both pipelines step by step. You will know how rebind removes web noise, how it finds bold text, headings, and code in a PDF, and where the reading layout comes from.

Source: internal/converter/ — converter.go, xhtml.go, pdf_converter.go, pdf_poppler.go, pdf_layout.go, pdf_statemachine.go, epub_hygiene.go.

0. Why you care, and the one idea under everything

An EPUB is a zip of small web pages. Inside the zip there are XHTML files (strict HTML), one CSS file, images, and a table of contents. An e-reader opens these pages and flows the text to fit its screen.

So both features have the same goal: produce clean XHTML plus one good stylesheet. The difference is the starting point.

Web URL

We start with too much structure. The page already has HTML tags, but also menus, ads, and buttons. The job is to remove.

PDF file

We start with no structure. A PDF only says "draw this text at this position, with this font." The job is to rebuild.

Analogy: the web pipeline is like cleaning a messy room — the furniture is there, you throw out the junk. The PDF pipeline is like rebuilding a room from a photo — you guess what each object is from its size and place. The analogy stops at one point: both pipelines finish in the same room, because they share the same stylesheet and the same EPUB packer.

A2. Walk through it (question 1)

1

You paste the URL and press Enter. The TUI is built with Bubble Tea (a Go framework for terminal apps). startConversion starts ConvertWithOptions in the background. It also opens a channel (a Go pipe between goroutines). The converter sends a progress event into this channel at each step, and the TUI shows it next to the spinner.

func (m Model) startConversion(rawInput string, isPDF bool) (tea.Model, tea.Cmd) {
    // 1. Open a buffered channel (a Go pipe that holds up to 16 events)
    ch := make(chan converter.ProgressEvent, 16)
    m.progressCh = ch

    // 2. Run ConvertWithOptions in the background and push events into the channel
    runCmd := func() tea.Msg {
        defer close(ch) // close the pipe when done
        res, err := converter.ConvertWithOptions(context.Background(), rawInput, converter.ConvertOptions{
            OutputDir: m.outputDir,
            Profile:   m.pdfTab.profile,
        }, func(ev converter.ProgressEvent) {
            select {
            case ch <- ev: // send event into the pipe
            default:       // never block if the buffer is full
            }
        })
        if err != nil {
            return errMsg{err: err}
        }
        return doneMsg{result: res}
    }

    // 3. Start three things at once: spinner, channel listener, and conversion
    return m, tea.Batch(m.spinner.Tick, waitForProgressCmd(ch), runCmd)
}

// Read one event from the pipe and hand it to Bubble Tea's Update loop
func waitForProgressCmd(ch <-chan converter.ProgressEvent) tea.Cmd {
    return func() tea.Msg {
        ev, ok := <-ch
        if !ok { return nil }
        return progressMsg(ev)
    }
}

2

rebind decides what you gave it. DetectInputKind removes quotes and checks: does a local file exist? Does the path end in .pdf? If not, it adds https:// when it is missing and parses the URL. A URL that ends in .pdf goes to the PDF pipeline. Every other URL goes to the web pipeline.

3

rebind downloads the page. fetchURLData sends an HTTP GET with a Safari User-Agent, because some sites block unknown clients. It follows redirects, waits up to 45 seconds, and reads up to 50 MB. If the reply is really a PDF (by Content-Type or the %PDF- magic bytes), it saves a temp file and switches to Part B.

4

Readability finds the article. The go-readability library returns the main content as HTML, plus the title, author, site name, short summary, and language. If the title is empty, rebind uses the domain name.

5

rebind downloads the images. It collects every <img> in the article and downloads up to 6 at the same time. It uses a buffered channel of size 6 as a counting semaphore (a 6-slot gate). It checks the real file type from the bytes, not from the URL. Each good image goes into the EPUB as img_0001.jpg, img_0002.png, and so on.

// 1. Walk the HTML tree and collect unique <img> URLs (including lazy data-src / srcset)
func ExtractImageURLs(rawHTML string, baseURL *url.URL) []string {
    doc, _ := html.Parse(strings.NewReader(rawHTML))
    seen := make(map[string]bool)
    var urls []string

    var walk func(*html.Node)
    walk = func(n *html.Node) {
        if n.Type == html.ElementNode && strings.EqualFold(n.Data, "img") {
            src := resolveImgSrc(n, baseURL) // checks src, data-src, data-lazy-src, srcset
            if src != "" && !seen[src] && (strings.HasPrefix(src, "http://") || strings.HasPrefix(src, "https://")) {
                seen[src] = true
                urls = append(urls, src)
            }
        }
        for c := n.FirstChild; c != nil; c = c.NextSibling {
            walk(c)
        }
    }
    walk(doc)
    return urls
}

// 2. Download up to 6 images at the same time with a channel semaphore
func downloadImagesConcurrently(ctx context.Context, urls []string, destDir string) map[string]string {
    results := make(map[string]string)
    var mu sync.Mutex
    var wg sync.WaitGroup
    sem := make(chan struct{}, 6) // 6-slot semaphore: at most 6 goroutines run inside at once
    client := &http.Client{Timeout: 15 * time.Second}

    for i, imgURL := range urls {
        wg.Add(1)
        go func(index int, rawURL string) {
            defer wg.Done()
            select {
            case sem <- struct{}{}:        // take 1 of the 6 slots (waits if all 6 are busy)
                defer func() { <-sem }()   // release the slot when this download finishes
            case <-ctx.Done():
                return
            }

            localPath, err := downloadSingleImage(ctx, client, rawURL, destDir, index)
            if err != nil { return }
            mu.Lock()
            results[rawURL] = localPath
            mu.Unlock()
        }(i, imgURL)
    }

    wg.Wait()
    return results
}

A3. How the noise is removed (question 2)

rebind removes noise in two layers. Each layer works at a different size. The first layer throws away whole page areas. The second layer cleans single tags and attributes inside the article.

Readability throws away whole areas of the page. The sanitizer then cleans the tags and attributes that are left inside the article.

Layer 1 — Readability: "which part of the page is the article?"

go-readability is a Go port of Mozilla Readability, the engine behind Firefox Reader View. It does not know any site. It uses simple scores:

  • It removes blocks whose class or id sounds like noise, for example comment, sidebar, footer, ad, share.
  • It gives points to paragraphs with long text and many commas. Real prose has commas. Menus do not.
  • It passes those points up to the parent blocks. The block with the highest total is the article.
  • It removes blocks with a high link density (mostly link text and little normal text). These are usually "related posts" lists.

Layer 2 — Sanitizer: "make every tag safe for an e-reader"

Readability's output is still normal web HTML. E-readers need XHTML: HTML that follows strict XML rules. Every tag must close, attribute values need quotes, and some characters are not allowed. One small error can make Apple Books reject the whole chapter. writeXHTMLNode walks the HTML tree and writes each node again from scratch. It applies three rules:

RuleWhat it doesExample
Drop list removeRemoves the tag and everything inside it.script, style, iframe, form, button, input, svg, canvas, video, audio
Attribute allowlist keepKeeps only 14 attributes. It removes all others.Keeps href, src, alt, id, class, colspan… Removes style, onclick, data-*, width
Unwrap flattenRemoves the tag but keeps its text.<a> with no link target, tags with names that are not valid XML
Where do background colors go? On most sites, colors and backgrounds come from the style="…" attribute or from site CSS. The sanitizer removes style and drops <style> tags. It never copies the site's CSS. So the page arrives with no colors at all. Only rebind's own stylesheet styles it.

The sanitizer also does some small repairs:

  • Lazy images: many sites put a blank placeholder in src and the real URL in data-src or srcset. resolveImgSrc finds the real one.
  • Offline images only: if an image failed to download, the sanitizer removes the <img>. Without this, Apple Books shows a broken-image icon when you read offline.
  • Relative links: it changes href="/about" to a full URL, so links still work from the e-reader.
  • Bad characters: it removes control characters that XML forbids, and escapes &, <, >.
  • Final check: validateXHTMLFragment runs the result through Go's XML decoder. If it fails, the conversion stops with an error, so you never get a broken EPUB.

A4. Where the reading format comes from (question 3)

The format comes from one CSS string in Go code: epubStylesheet in converter.go. rebind writes it into the EPUB as style.css and links it from every chapter. The site's own CSS never enters the book. The web pipeline and the PDF pipeline use the same stylesheet.

Every chapter links to one shared stylesheet. The dashed boxes are book metadata that go-epub writes and PostProcessEPUB repairs.

The main design choices in the stylesheet:

ConcernRule in epubStylesheetWhy
Body textfont-family: "Iowan Old Style", Georgia, …, serif
line-height: 1.68		A book serif and open line spacing are easy to read for a long time.
Page paddingbody { padding: 0.5em 0.8em; margin: 0 auto }Small padding. The e-reader adds its own margins, so a big value would waste space.
Paragraph spacingp { margin: 0 0 1em 0 }One empty line between paragraphs, no first-line indent, like a web article.
Headingsmargin-top: 1.5em; margin-bottom: 0.5em; line-height: 1.3More space above than below, so a heading sits close to its own text.
Line breaksoverflow-wrap: break-word; in pre: white-space: pre-wrapLong URLs and long code lines wrap. They do not run off a small screen.
Page breakspage-break-inside: avoid on img, figureThe reader does not cut an image in half between two pages.
Imagesmax-width: 100%; height: auto; display: block; margin: 1.2em autoImages shrink to the screen width and sit centered.
CodeMonospace font at 0.88em, light gray box, 1px borderCode looks different from prose, but stays readable.
ColorsOnly rgba(128,128,128, α) grays. The body has no color.Semi-transparent gray looks right on white, sepia, and dark mode. Kindle and Apple Books choose the text color.
Every size is in em, not pixels. One em equals the current font size. When you make the font bigger on your Kindle, the padding, margins, and spaces grow with it. The layout keeps the same shape at every font size.

Part B — PDF file to EPUB

B0. First, what a PDF really contains

A PDF is a set of drawing instructions for fixed pages. It does not say "this is a heading" or "this is a paragraph." It says "draw the text Chapter 1 at x=120, y=200, in font Georgia-Bold, size 28." rebind uses Poppler (a free PDF toolkit: brew install poppler) to read these instructions as XML.

Each colored box on the page becomes one or more <text> pieces with a top, a left, and a font id. Nothing says "heading" or "code". rebind must guess from size, font name, and position.

Analogy: the PDF pipeline is a detective. The clues are position (where), size (how big), font name (what style), and gaps (how far apart). The analogy stops here: a detective can ask questions. rebind cannot, so it uses fixed thresholds that work for most books.

B1. In one picture

The PDF pipeline has more amber "work" boxes than the web pipeline, because it must rebuild the structure that a web page already has.

B2. Walk through it (question 1)

1

Read the PDF with Poppler. pdfinfo gives the title, author, and page count. rebind ignores useless titles like "Untitled" or "Microsoft Word - …". pdftohtml -xml writes book.xml, which has every text piece, every font, the image files, and the PDF bookmarks (the outline).

2

Join text pieces into visual lines. One printed line is often split into many pieces, for example at each font change. BuildVisualLines sorts pieces top to bottom, then left to right. It groups pieces whose baselines (the bottom edges of the letters) are within about 3.5 points. The result is a visual line: one line of text with its position, size, and main font.

3

Remove page noise and fix reading order. StripRunningNoise looks at the top 8.5% and the bottom 8.5% of each page. It removes page numbers and any line that repeats on many pages (the book title, the chapter name). Before it compares, it changes every digit to #, so "Page 12" and "Page 13" count as the same line. SplitPageColumns finds two-column pages and puts the left column before the right column.

4

Learn about the whole book. rebind computes the median font size (the size of normal body text) and the median line pitch (the normal distance between two lines). Later rules compare against these two numbers. It also picks a profile: technical if the book has enough monospace text, code-like lines, or "Figure 3" captions; otherwise fiction. Last, it builds a lexicon: a count of every word in the book, used later to fix hyphenated words.

5

Classify each line. A state machine (a loop that checks a fixed list of cases in order) reads lines from top to bottom. It decides: scene break, table, heading, code, list, or paragraph. Each decision makes a ParsedBlock of XHTML. Section B3 explains this step.

6

Handle images. rebind finds the cover on the first 3 pages, adds the normal images, and cuts out diagrams and large tables as PNG pictures. Section B3 explains this step too.

7

Split into chapters. splitBlocksIntoChapters tries three ways, in order: (A) the PDF bookmarks, (B) the detected h1 headings, (C) groups of 20 pages. Then it joins paragraphs that a page break cut in two, and keeps only one h1 per chapter file.

8

Package and save. rebind checks each chapter with the XML parser. If a chapter fails, the web sanitizer cleans it. Then rebind adds the same stylesheet as the web pipeline, writes the zip, and runs the same TOC fix.

B3. How rebind finds bold, italic, headings, code, and images (question 2)

There are no tags, so every format comes from one of four clues. This table is the short answer. The parts below give the detail.

FormatMain clueOutput
Bold / italicThe font name contains "Bold" or "Italic", or Poppler marked it with <b>/<i><strong>, <em>
Underline, strikethroughOnly if Poppler marked it with <u>/<s><u>, <del>
HeadingsFont size compared to the median body size, plus bold and spacing<h1>, <h2>, <h3>
Code blockMonospace font name, box-drawing characters, or code keywords<pre><code> with rebuilt indentation
ImageImage files from Poppler, or an empty area above a "Figure N" caption<figure><img><figcaption>

Bold, italic, underline: read the font name

Fonts inside a PDF often have names like ABCDEF+Georgia-BoldItalic. The six letters and the plus sign are a subset prefix (a tag that says the PDF only includes the letters it uses). classifyFont removes the prefix and searches the name for word parts:

  • Bold: bold, black, heavy, demi, semibold
  • Italic: italic, oblique, slanted
  • Monospace: mono, courier, consolas, menlo, jetbrains, fira code, and others

Poppler also writes inline tags such as <b>, <i>, <u>, and <s> inside a text piece. parseInnerXML changes these to safe XHTML (<strong>, <em>, <u>, <del>) and drops every other tag.

One more rule keeps the output clean. In each visual line, the font with the most characters is the dominant font. rebind wraps a piece in <strong> only when that piece is bold and the dominant font is not bold. So one bold word in a sentence becomes <strong>, but a fully bold heading line does not get a <strong> around every word. Italic and monospace work the same way. A monospace word inside normal text becomes inline <code>.

Underline is weak in PDFs. Most PDFs draw an underline as a separate thin line shape, not as a text style. Poppler only gives text, so rebind keeps an underline only when Poppler marks it with <u>. Most underlines are lost. Bold and italic are reliable, because they live in the font name.

Headings: compare the size to normal text

"Big" only means something when you compare it to normal text. So rebind compares every line to the median font size of the book. The median ignores a few very large or very small lines, so it is a good measure of the body text size.

Size picks h1 and h2. An h3 has the same size as body text, so rebind finds it by its bold font and the space around it.

Extra rules stop wrong headings:

  • A line is not a heading if it is in the bottom 15% of the page, if it is only digits and symbols, or if it has more than one sentence.
  • An h1 that comes after a paragraph on the same page becomes an h2. A chapter title starts a page. It does not appear in the middle.
  • Two heading lines in a row join into one heading. For example, "Chapter 1" + "The Long Road" become one heading.
  • Each chapter file keeps only one h1. Any other h1 becomes an h2.

Code blocks: monospace font, then rebuild the spaces

A line starts a code block when it is monospace, has 2 or more box-drawing characters (┌ ─ │ └, used in ASCII diagrams), or, in the technical profile only, starts with a code word like func , def , class , {, or //. rebind keeps adding the next lines while they are close together, not left of the first line, and not much bigger.

Spaces are the hard part. A PDF does not keep space characters at the start of a line. It just draws the text further to the right. So renderCodeBlock turns that distance back into spaces:

char_width  = font_size × 0.58          # a monospace letter is about 0.58 em wide
indent      = round((line.left − leftmost_line.left) ÷ char_width)
blank lines = round(gap ÷ normal_pitch) − 1   (at most 2)

Example: run() starts 12 points right of func main() {. With a 10-point font, the character width is 5.8 points, so 12 ÷ 5.8 ≈ 2 spaces. A large vertical gap between two code lines becomes an empty line inside the <pre>.

Images: three sources

1

Normal images. pdftohtml saves each photo or bitmap as a file. rebind adds it to the EPUB. Then it looks for a caption within 45 points above or below the image. A caption is a line that starts with "Figure N", is italic, or uses a smaller font.

2

Vector diagrams. Many diagrams are drawn with lines and shapes, not stored as image files. Poppler gives no file for them. rebind's clue: a "Figure 3" caption with an empty gap of 70 points or more above it. Something is drawn in that gap. pdftoppm renders that area at 300 DPI and saves it as a PNG.

3

Large tables and sliced images. A table with more than 3 columns or more than 30 rows would look bad as HTML on a small screen, so rebind saves it as a picture. Some PDFs also cut one picture into hundreds of thin strips. When rebind finds 4 or more strips stacked together, it renders the whole area as one PNG.

The cover is a separate check. On the first 3 pages, any image that covers 65% or more of the page width and height becomes the EPUB cover.

Order matters. A big bold line could match both "h1" and "h3". The state machine checks h1 first, so the line becomes h1. Paragraph is last. It is the default when nothing else matches.

B4. Where the reading format comes from (question 3)

The PDF pipeline uses the same epubStylesheet as the web pipeline (see A4). The font, line height, padding, image rules, and code box are the same. The PDF work is different in one way: before CSS can style a paragraph, rebind must first decide where each paragraph starts and ends. A PDF has a hard line break at the end of every printed line. A Kindle screen has a different width, so those breaks must go.

Joining lines into paragraphs

collectParagraphLines adds the next line to the current paragraph, but stops when one of these is true:

Stop signalWhy it means "new paragraph"
The previous line ends with . ! ? : and stops before the right marginA short last line is how a printed paragraph ends.
The next line is indented and the previous one ended a sentenceBooks indent the first line of a new paragraph.
The gap between lines is more than 1.6 × the normal pitchExtra space means a new block.
The next line starts with a quote mark or a dashIn fiction, each line of dialogue is its own paragraph.
The next line looks like a heading, code, a list, or a captionA different block type starts.

Two repairs happen when the lines join:

  • Hyphen fix. "inter-" at the end of a line plus "national" on the next line. Is the word "international" or "inter-national"? Dehyphenate checks the lexicon from step 4. If the book uses "international" more often, rebind joins it. If the book uses the hyphenated form, rebind keeps the hyphen.
  • Page break fix. mergeCrossPageParagraphs joins the last paragraph of a page with the first paragraph of the next page. It does this if the first one does not end a sentence, or if the second one starts with a lowercase letter.

Common confusions

"The sanitizer is what removes ads." Mostly not. Readability removes ads, menus, and comments, because it throws away whole page areas. The sanitizer works on the small details that remain, such as tags and attributes.
"rebind keeps the website's look." No. rebind removes all site CSS and inline styles on purpose. Every book uses the same stylesheet. This is why the result looks the same on Kindle and Apple Books, and why dark mode works.
"pdftohtml converts the PDF to HTML for us." Only in a basic way. rebind uses its -xml mode, which gives positioned text pieces and nothing more. All paragraphs, headings, code blocks, chapters, and figures come from rebind's own rules in pdf_layout.go and pdf_statemachine.go.
"Big text is always a heading." Not always. A drop cap is big but is the first letter of a paragraph. A big line at the bottom of a page is not a heading. Sizes are compared to the median of this book. A 14-point line is a heading in a 10-point book, but body text in a 14-point book.
"Fiction vs technical profile changes the CSS." No. The profile only changes detection. In the technical profile, lines that start with code words like func or { can start a code block. The stylesheet stays the same.
